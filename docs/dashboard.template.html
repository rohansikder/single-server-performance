A finding worth discussing

Cache locking has a latency budget, too.

An initial five-VU journey observed about 501 ms p95 with the default lock behavior. The final configuration caps cache-lock waiting at 100 ms. Timed-out waiters query upstream, trading some extra reads for less waiting.

What the before / after does and does not prove

These are tiny randomized runs with 27 and 26 HTTP requests, different cache warmth, and different scheduling. They are not a controlled effect-size estimate. The final journey passed all route and error checks; the explicit wait budget is a reproducible configuration choice.
